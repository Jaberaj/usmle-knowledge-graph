# Application contract v1.1.0

Applications consume UTF-8 snake_case JSON in `dist/json`, not source table internals. `manifest.json` contains versions, counts, SHA-256 checksums, build metadata, compatibility notes, and disclaimer. `entities.json` and `relationships.json` expose normalized records, including `entity_references` for traceable source support. Disease, presentation, treatment, medication, algorithm, game, and search bundles are deterministic application-ready projections. Clients must surface source status and human-review status separately; human review is never an eligibility requirement. `content_tier` and per-record `eligibility` express learning-game completeness. Keywords and complication relationships are exposed in the normalized bundles. Legacy review fields remain during the backward-compatible migration.
